## UC-16

* **ID / Code:** UC-16
* **Use Case Name:** Resolve a billing or delivery issue
* **Description:** Track a customer issue to resolution, including internal evidence and a separately authorised follow-up suspension.
* **Primary Actor:** Operational User
* **Supporting Actors:** None
* **Scope:** Turbine internal invoicing and collections application.
* **Level:** User Goal
* **Related requirements:** BR-02, BR-04, BR-06; UR: UR-05; FR: FR3.4, FR12, FR12.1, FR12.2, FR12.3; NFR-02, NFR-04, NFR-05.
* **Source:** E pp. 5-6, 10-11, 15.
* **Stakeholders & Interests:**
  * *Assigned staff:* coordinate the issue owner and corrective action.
  * *Customer:* have billing problems followed up.
  * *Administrator:* control restricted notes and financial exceptions.
* **Preconditions:** The actor is authenticated with issue-management permission and access to the customer/invoice.
* **Postconditions:** The issue retains owner, status, history and resolution; any reminder pause has its own reason/review date and does not erase debt.
* **Success Guarantee:** A tracked issue has an operational resolution or remains explicitly pending with an owner.
* **Minimal Guarantee:** Internal comments are not sent to customers and issue closure alone changes no invoice amount or paid status.
* **Trigger:** Staff report a problem or invoice delivery/payment matching creates an exception.
* **Main Success Scenario:**
1. The Operational User records the customer, optional invoice, issue type, description, priority and owner.
2. The system stores the issue.
3. The system notifies the owner.
4. The Operational User records internal findings.
5. The Operational User performs the corrective workflow under its separate authority.
6. The Operational User records the resolution after the actual corrective action.
7. The system stores closure and its history.
8. The system reviews any related reminder pause.

* **Extensions:**
  * **1a.** Delivery problem from [UC-20](UC-20.md):
    1. The Operational User opens the issue as a conditional extension of [UC-20](UC-20.md) when delivery follow-up is needed.
  * **1b.** Reconciliation problem from [UC-07](UC-07.md):
    1. The Operational User opens the issue as a conditional extension of [UC-07](UC-07.md) when reconciliation follow-up is needed.
  * **4a.** Internal comment:
    1. The Operational User adds an internal comment.
    2. The system retains the comment without sending it to the customer.
  * **4b.** Mention added:
    1. The Operational User mentions another user.
    2. The system notifies the mentioned user within permitted scope.
  * **4c.** Administrative note:
    1. The Administrator records a restricted note.
    2. The system restricts its visibility to administrators.
  * **4d.** Attachment added:
    1. The Operational User supplies a document with type and description.
    2. The system checks its format and size.
    3. The system stores the permitted attachment under the associated customer or invoice scope.
  * **4e.** Disallowed attachment format:
    1. The system rejects the attachment with the format reason.
  * **4f.** Oversize attachment:
    1. The system rejects the attachment with the size reason.
  * **4g.** Expired download link:
    1. The system rejects the expired link without widening access.
  * **5a.** Collection pause requested:
    1. The Operational User supplies a pause reason and review date.
    2. The system checks suspension authority.
    3. The system records the justified pause without erasing unpaid debt.
    4. The system suppresses automatic reminders for that pause under [UC-08](UC-08.md).
  * **5b.** Pause authority missing:
    1. The system denies suspension without stopping follow-up merely because an issue exists.
  * **5c.** Payment allocation needed:
    1. The Operational User invokes [UC-07](UC-07.md) with reconciliation authority.
  * **5d.** Invoice correction needed:
    1. The authorised Administrator invokes [UC-15](UC-15.md) with correction authority.
  * **5e.** Delivery retry needed:
    1. The Operational User invokes [UC-20](UC-20.md) for the existing invoice.
  * **6a.** Issue unresolved:
    1. The system retains the pending issue with its owner.
  * **8a.** Pause review due before resolution:
    1. The system notifies the owner.
    2. The system applies the documented resumption policy without marking debt paid.
