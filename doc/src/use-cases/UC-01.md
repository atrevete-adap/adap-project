## UC-01

* **ID / Code:** UC-01
* **Use Case Name:** Access the internal application
* **Description:** Authenticate an internal staff member and open the work area permitted by their corporate account.
* **Primary Actor:** Operational User
* **Supporting Actors:** Communication Service (password recovery)
* **Scope:** Turbine internal invoicing and collections application.
* **Level:** User Goal
* **Related requirements:** BR-01, BR-04; UR: UR-12; FR: FR6.1, FR6.2; NFR-02, NFR-04.
* **Source:** E pp. 7-8, 12.
* **Stakeholders & Interests:**
  * *Internal staff:* obtain access to their work.
  * *Turbine:* restrict access to active corporate accounts.
* **Preconditions:** An internal account has been provisioned; login itself requires no existing session.
* **Postconditions:** Successful login creates a session with current permissions; rejection creates none. Logout, expiry or deactivation invalidates access.
* **Success Guarantee:** The authenticated user reaches the work area allowed by their role and customer scope.
* **Minimal Guarantee:** No protected customer information is disclosed to an unauthenticated requester.
* **Trigger:** A staff member requests access.
* **Main Success Scenario:**
1. The Operational User enters their corporate email and password.
2. The system checks the authorised email domain.
3. The system checks that the account is active and verified.
4. The system verifies the credentials.
5. The system creates a session with the current permissions.
6. The system opens the scoped work area in [UC-09](UC-09.md).

* **Extensions:**
  * **2a.** Unauthorised domain:
    1. The system rejects access with a generic message.
    2. The system applies the configured failed-attempt protection.
  * **3a.** Inactive account:
    1. The system rejects access with the same generic message.
  * **3b.** Unverified account:
    1. The system rejects access with the same generic message.
  * **4a.** Invalid credentials:
    1. The system rejects access with the same generic message.
    2. The system applies the configured failed-attempt protection.
  * **1a.** Forgotten password:
    1. The Operational User requests recovery.
    2. The system requests an expiring, single-use recovery link for an eligible account through Communication Service.
    3. The system shows a response that does not disclose whether an account exists.
  * **6a.** Logout requested:
    1. The Operational User requests logout.
    2. The system invalidates the session.
  * **6b.** Inactivity limit reached:
    1. The system expires the session.
    2. The system requires authentication for further protected access.
  * **6c.** Account deactivated:
    1. The system invalidates the session.
    2. The system requires authentication for further protected access.
