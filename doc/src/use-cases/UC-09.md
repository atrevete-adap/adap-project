## UC-09

* **ID / Code:** UC-09
* **Use Case Name:** Review daily work and notifications
* **Description:** Find scoped tasks and notifications, search operational records and open the workflow needed to act.
* **Primary Actor:** Operational User
* **Supporting Actors:** None
* **Scope:** Turbine internal invoicing and collections application.
* **Level:** User Goal
* **Related requirements:** BR-02, BR-04; UR: UR-10; FR: FR7, FR7.1, FR7.2, FR8.2, FR8.3; NFR-02, NFR-03, NFR-04, NFR-05.
* **Source:** E pp. 6-8.
* **Stakeholders & Interests:**
  * *Assigned staff:* prioritise actionable work.
  * *Administrator:* review the permitted wider queue.
  * *Customer:* avoid debt being treated as resolved merely because an alert was read.
* **Preconditions:** The user is authenticated; tasks, search results and notifications are restricted to current scope.
* **Postconditions:** Read/handled notification states are stored independently of actual payment or issue resolution; opening records rechecks access.
* **Success Guarantee:** The user locates authorised work and can follow it to the relevant operational case.
* **Minimal Guarantee:** Reading an alert neither settles debt nor grants access to an out-of-scope record.
* **Trigger:** Login opens the work screen or the user searches/reviews a notification.
* **Main Success Scenario:**
1. The system lists scoped due and overdue invoices, reconciliation work, dispatch failures, approvals, annual reviews and assigned tasks.
2. The Operational User searches or filters permitted customer, contact and invoice fields.
3. The Operational User opens an item.
4. The system rechecks access to the selected record.
5. The system opens the corresponding operational workflow: [UC-04](UC-04.md) for annual reviews, [UC-07](UC-07.md) for reconciliation, [UC-16](UC-16.md) for issues or [UC-17](UC-17.md) for approvals.
6. The Operational User marks a notification as read or handled.
7. The system stores the notification state independently of the underlying operational outcome.

* **Extensions:**
  * **2a.** Named view requested:
    1. The Operational User saves the current search and filters as a named view.
  * **2b.** Quick access requested:
    1. The Operational User selects a favourite or one of the ten most recently opened customers.
    2. The system rechecks current scope.
  * **4a.** Assignment changed:
    1. The system denies the inaccessible target details.
    2. The system refreshes the permitted list.
  * **4b.** Access revoked:
    1. The system denies target details.
    2. The system refreshes the permitted list.
  * **5a.** Invoice work selected:
    1. The system opens [UC-05](UC-05.md) for a draft, [UC-19](UC-19.md) for issuance or [UC-20](UC-20.md) for delivery under the selected operation permission.
  * **7a.** Overdue alert read without resolving debt:
    1. The system retains the outstanding debt and unresolved operational state.
  * **1a.** Administrator global operational view:
    1. The system checks global inbox permission.
    2. The system displays permitted operational items without granting a financial dashboard to an Operational User.
  * **1b.** Notification preference change:
    1. The Operational User selects permitted immediate email, in-app or daily digest preferences.
    2. The system retains in-app events under FR7 and FR7.1.
  * **1c.** Parameterised alert rule:
    1. The Administrator selects a condition from the closed supported set under FR7.2.
    2. The system stores the authorised alert parameters.
