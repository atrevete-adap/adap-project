## UC-18

* **ID / Code:** UC-18
* **Use Case Name:** Close or reopen an administrative period
* **Description:** Close a reviewed month/quarter or exceptionally reopen it with higher authority and an audited reason.
* **Primary Actor:** Administrator
* **Supporting Actors:** None
* **Scope:** Turbine internal invoicing and collections application.
* **Level:** User Goal
* **Related requirements:** BR-04, BR-06; UR: UR-09; FR: FR13.2; NFR-04, NFR-05, NFR-06.
* **Source:** E pp. 3, 14.
* **Stakeholders & Interests:**
  * *Administrator:* control post-review changes.
  * *Accounting firm:* receive a stable accounting period.
  * *Turbine finance staff:* retain traceable corrections and period history.
* **Preconditions:** The actor has period-closing authority and the period exists; reopening additionally requires higher capability and a reason.
* **Postconditions:** The confirmed period state and close/reopen event are stored and enforced on later operations; rejected requests leave the former state.
* **Success Guarantee:** The authorised state transition is audited and subsequent financial checks enforce it.
* **Minimal Guarantee:** Closing/reopening neither erases debt nor permits silent rewriting of issued invoices.
* **Trigger:** An Administrator requests closure or exceptional reopening.
* **Main Success Scenario:**
1. The Administrator selects the month or quarter.
2. The Administrator reviews its records and unresolved exceptions.
3. The system previews the closing restrictions.
4. The system checks for blocking financial changes.
5. The Administrator confirms closure with a reason.
6. The system records the period state with actor, time and reason.
7. The system enforces the state on subsequent financial operations.

* **Extensions:**
  * **1a.** Exceptional reopening requested:
    1. The Administrator supplies the reopening reason.
    2. The system checks the required higher capability.
    3. The system previews the reopening consequences.
    4. The Administrator confirms reopening.
    5. The system records the new state without deleting the earlier closure event.
  * **4a.** Blocking exception:
    1. The system rejects closure with the exception details.
  * **4b.** Concurrent financial change:
    1. The system rejects the conflicting closure with the conflict details.
  * **7a.** Correction requested after reopening:
    1. The system routes the change through [UC-15](UC-15.md) without allowing an original issued invoice to be overwritten.
