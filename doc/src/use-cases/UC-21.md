## UC-21

* **ID / Code:** UC-21
* **Use Case Name:** Create a data and document backup
* **Description:** Create a traceable restorable backup of data and documents under the configured policy.
* **Primary Actor:** None for scheduled execution; Super Administrator for manual backup
* **Other Initiating Contexts:** Scheduled backup creation is internal system behaviour. The Scheduler is an architecture component and has no external actor role.
* **Supporting Actors:** None
* **Scope:** Turbine internal invoicing and collections application.
* **Level:** User Goal
* **Related requirements:** BR-01, BR-04, BR-06; UR: UR-14; FR: FR9, FR9.2; NFR-04, NFR-05, NFR-06.
* **Source:** E pp. 8-9, 12.
* **Stakeholders & Interests:**
  * *Super Administrator:* diagnose failures and recover a validated state.
  * *Turbine:* retain intact financial history and usable backups.
  * *Customer:* retain documents and scoped access after recovery.
* **Preconditions:** A backup policy with authorised scope exists. Manual creation requires authenticated Super Administrator backup authority. Automatic creation uses the configured policy without a human initiator.
* **Postconditions:** The attempt retains scope, time, outcome and backup validity. A failed attempt leaves the last valid backup available; recovery is a separate [UC-22](UC-22.md) operation.
* **Success Guarantee:** A validated data-and-document backup is available with traceable scope and outcome.
* **Minimal Guarantee:** An incomplete or invalid backup is not presented as restorable. Backup creation never changes financial history or starts restoration.
* **Trigger:** A configured backup occurrence becomes due, or the Super Administrator requests a manual backup.
* **Main Success Scenario:**
1. The system identifies the backup scope under the configured policy.
2. The system records the backup attempt.
3. The system creates the data-and-document backup.
4. The system validates backup completeness and usability.
5. The system records the scope, time, validity and outcome.
6. The system updates the last-successful-backup status available in [UC-14](UC-14.md).

* **Extensions:**
  * **1a.** Manual creation requested:
    1. The Super Administrator selects the backup scope.
    2. The system checks backup authority.
    3. The flow continues at step 2.
  * **1b.** Manual backup permission missing:
    1. The system rejects access to protected backup creation and details.
  * **3a.** Backup creation fails:
    1. The system retains the last valid backup.
    2. The system records the failed stage.
    3. The system notifies the responsible operator.
  * **4a.** Backup invalid:
    1. The system records the invalid outcome without replacing the last valid backup.
    2. The system notifies the responsible operator.
  * **6a.** Backup interval target at risk:
    1. The system exposes the policy failure under the NFR-05 requirement for backups at least every 24 hours.
    2. The system notifies the responsible operator.
