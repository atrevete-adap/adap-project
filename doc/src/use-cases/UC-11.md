## UC-11

* **ID / Code:** UC-11
* **Use Case Name:** Query outstanding obligations through the API
* **Description:** Return an authorised, time-stamped customer debt snapshot without mutating billing or cancellation state.
* **Primary Actor:** External Application
* **Other Initiating Contexts:** [UC-10](UC-10.md) invokes debt calculation using its authorised internal context, without external API credentials.
* **Supporting Actors:** None
* **Scope:** Turbine internal invoicing and collections application.
* **Level:** User Goal
* **Related requirements:** BR-01, BR-02; UR: UR-02; FR: FR4.2, FR15, FR15.1, FR15.2; NFR-03, NFR-04, NFR-05, NFR-07.
* **Source:** E pp. 4, 11-12.
* **Stakeholders & Interests:**
  * *External Application:* distinguish valid debt results from errors.
  * *Turbine:* limit disclosure to scoped callers.
  * *Customer:* have obligations calculated from financial evidence.
* **Preconditions:** External calls require provisioned API credentials and debt-query scope; the [UC-10](UC-10.md) internal include uses its already-authorised workflow/customer context.
* **Postconditions:** A successful response provides permitted debt details, currency and snapshot time; rejected/unavailable queries leave all business state unchanged.
* **Success Guarantee:** The caller receives a documented, scoped debt snapshot.
* **Minimal Guarantee:** An error is never reported as debt-free, and a query cannot cancel recurrence.
* **Trigger:** An External Application requests debt status or [UC-10](UC-10.md) invokes its internal calculation.
* **Main Success Scenario:**
1. External Application supplies the customer identifier and its API authority.
2. The system verifies API authentication.
3. The system checks customer scope and applicable call limits.
4. The system calculates obligations from issued invoices, verified payments and corrective documents in separate currencies.
5. The system returns the permitted debt indicators and details with their currency and snapshot time.
6. The system records the important call.

* **Extensions:**
  * **1a.** [UC-10](UC-10.md) internal include:
    1. The system uses the already-authorised [UC-10](UC-10.md) workflow and customer context in place of external API credentials.
    2. The flow continues at step 4.
  * **2a.** Invalid API authority:
    1. The system returns the documented non-disclosing authentication error.
  * **3a.** Insufficient query scope:
    1. The system returns the documented non-disclosing access error.
  * **3b.** Inaccessible customer:
    1. The system returns the documented non-disclosing customer error.
  * **3c.** Call limit exceeded:
    1. The system returns the documented limit response without calculating debt.
  * **4a.** Calculation unavailable:
    1. The system returns an explicit error without substituting zero debt.
  * **5a.** Later financial state change:
    1. The system requires [UC-10](UC-10.md) to recheck current data before cancellation confirmation.
  * **1b.** Other documented customer or invoice query under FR15:
    1. External Application supplies the documented query.
    2. The system applies its permitted fields, scope and interface rules.
  * **1c.** Controlled cancellation intake:
    1. The system routes the request to [UC-10](UC-10.md) without granting external cancellation-confirmation authority.
