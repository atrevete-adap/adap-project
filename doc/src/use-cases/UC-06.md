## UC-06

* **ID / Code:** UC-06
* **Use Case Name:** Generate monthly recurring invoices
* **Description:** Process eligible monthly subscriptions and recover interrupted billing runs without repeating a subscription-period charge.
* **Primary Actor:** None (automatic system behaviour)
* **Supporting Actors:** None
* **Scope:** Turbine internal invoicing and collections application.
* **Level:** Summary
* **Related requirements:** BR-02, BR-03, BR-06; UR: UR-03, UR-10; FR: FR2.1, FR9.2, FR14, FR11.2, FR14.3; NFR-03, NFR-05, NFR-06.
* **Source:** E pp. 4, 9, 14, 17.
* **Stakeholders & Interests:**
  * *Turbine:* complete scheduled billing after failures.
  * *Customer:* avoid duplicate or ineligible charges.
  * *Assigned staff:* receive actionable item failures.
* **Preconditions:** An authorised billing schedule, subscriptions and effective terms exist.
* **Postconditions:** The run records generated, skipped and failed items. Each successful eligible subscription-period refers to its single invoice and failures retain a recoverable stage.
* **Success Guarantee:** Eligible independent items are processed once and the execution exposes its actual completion/error status.
* **Minimal Guarantee:** One failed item does not duplicate successful invoices or block independent subscriptions.
* **Trigger:** The first day of the month becomes due under the [UC-13](UC-13.md) billing policy, or the system recovers a missed or interrupted run.
* **Main Success Scenario:**
1. The system opens the billing-period execution record.
2. The system selects subscriptions eligible under their start, pause, cancellation, rate and discount effective dates.
3. The system performs [UC-05](UC-05.md) for each unprocessed subscription-period using its approved recurring proposal.
4. The system performs [UC-19](UC-19.md) for the resulting draft under approved subscription authority.
5. The system records each item outcome and its invoice reference.
6. The system notifies responsible staff of actionable failures.
7. The system records the run totals and actual completion status.

* **Extensions:**
  * **2a.** Paused subscription:
    1. The system skips generation without changing previous debt.
  * **2b.** Future subscription:
    1. The system skips generation until activation without changing previous debt.
  * **2c.** Effectively cancelled subscription:
    1. The system skips generation without changing previous debt.
  * **3a.** Duplicate or concurrent run for the same subscription-period:
    1. The system reuses the recorded invoice or in-progress outcome without issuing again.
  * **3b.** Draft validation fails:
    1. The system records the failed validation stage.
    2. The system continues independent items.
    3. The system resumes only the missing work on recovery.
  * **4a.** Issuance fails:
    1. The system records the failed [UC-19](UC-19.md) stage.
    2. The system continues independent items.
    3. The system resumes that stage without a second invoice.
  * **4b.** Issued PDF unavailable:
    1. The system retains the existing invoice number and snapshot under [UC-19](UC-19.md).
    2. The system continues independent items.
    3. The system retries only the missing PDF.
  * **4c.** Delivery fails in the [UC-20](UC-20.md) included by [UC-19](UC-19.md):
    1. The system retains the issued invoice and failed delivery outcome.
    2. The system continues independent items.
    3. The system retries only [UC-20](UC-20.md) for that invoice.
  * **1a.** Outage or missed generation:
    1. The system identifies missing periods and items on recovery without requiring an open staff session.
    2. The system resumes the recorded stage for each missing item.
