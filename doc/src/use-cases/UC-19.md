## UC-19

* **ID / Code:** UC-19
* **Use Case Name:** Issue an invoice
* **Description:** Turn one authorised draft into a uniquely numbered immutable invoice with its preserved corporate PDF and a separately tracked delivery request.
* **Primary Actor:** Operational User
* **Other Initiating Contexts:** [UC-04](UC-04.md) requests initial prorated issuance. [UC-06](UC-06.md) and [UC-15](UC-15.md) include issuance using their authorised subscription or correction context without requiring a new staff session.
* **Supporting Actors:** Communication Service (through [UC-20](UC-20.md))
* **Scope:** Turbine internal invoicing and collections application.
* **Level:** User Goal
* **Related requirements:** BR-04, BR-06; UR: UR-03, UR-04; FR: FR2.3, FR2.4, FR2.5, FR2.6, FR11.2, FR14.4; NFR-01, NFR-02, NFR-04, NFR-05, NFR-06.
* **Source:** E pp. 3-5, 16.; E pp. 3-5, 8-9, 14.; E pp. 5, 12, 15.
* **Stakeholders & Interests:**
  * *Customer and billing recipients:* receive a correct invoice through an eligible channel.
  * *Assigned staff:* prepare invoices and resolve delivery failures.
  * *Turbine finance staff:* preserve numbering, issued amounts and dispatch evidence.
* **Preconditions:** A current draft prepared in [UC-05](UC-05.md) exists. Direct issuance requires authentication, issuance permission and customer scope. Internal calls use the approved subscription or correction authority. Series, taxes and corporate templates are configured; required approvals and period authority must hold at issuance.
* **Postconditions:** Successful issuance preserves one number, immutable snapshot and original PDF. The [UC-20](UC-20.md) delivery outcome is separate. A PDF failure after issuance retains the same number and snapshot with the document stage incomplete.
* **Success Guarantee:** One authorised draft becomes one issued invoice with its original PDF and a recorded delivery attempt or recoverable dispatch request.
* **Minimal Guarantee:** Rejected drafts consume no definitive number. Repeated requests return the existing outcome. Failures after issuance never renumber or duplicate the invoice and never invent delivery or read evidence.
* **Trigger:** Staff request issuance of a current draft, or an authorised [UC-04](UC-04.md), [UC-06](UC-06.md) or [UC-15](UC-15.md) workflow reaches its issuance stage.
* **Main Success Scenario:**
1. The system receives the current draft and its issuance authority.
2. The system rechecks customer scope and mandatory invoicing tax data.
3. The system rechecks totals, single currency and draft version.
4. The system verifies the approval status for the exact proposal.
5. The system checks the [UC-18](UC-18.md) period restrictions.
6. The system presents the final preview to the authorised Operational User.
7. The Operational User confirms issuance.
8. The system assigns the unique sequential series number to the issued snapshot.
9. The system generates the corporate PDF with issuer tax data, number, dates, lines, tax bases, taxes, total, payment terms and support details.
10. The system preserves the original PDF linked to the issued invoice and customer.
11. The system performs [UC-20](UC-20.md) for the issued invoice.
12. The system records the separate issuance, PDF and dispatch outcomes.

* **Extensions:**
  * **2a.** Missing mandatory data:
    1. The system blocks issuance with the missing fields.
    2. The system preserves the recoverable draft.
  * **3a.** Invalid totals:
    1. The system blocks issuance with the validation reason.
    2. The system preserves the draft.
  * **3b.** Stale proposal version:
    1. The system rejects the stale request without overwriting the current draft.
  * **3c.** Unusual amount:
    1. The system shows the configured non-blocking deviation warning under FR2.5.2.
  * **3d.** Invalid currency:
    1. The system blocks issuance with the currency reason.
    2. The system preserves the draft.
  * **4a.** Sensitive financial approval required:
    1. The system invokes [UC-17](UC-17.md) for the exact manual amount change, extraordinary discount, unusual due date or threshold-sensitive invoice.
    2. The system waits for the required decision before issuance.
  * **4b.** Approval pending:
    1. The system retains the proposal without issuing or sending.
  * **4c.** Approval rejected:
    1. The system retains the rejection without issuing or sending.
  * **4d.** Unchanged approved subscription proposal:
    1. The system applies the FR11.2 approval exemption.
  * **5a.** Closed period without exceptional authority:
    1. The system blocks issuance under [UC-18](UC-18.md) rules.
  * **6a.** Approved automated caller:
    1. The system verifies the caller-approved proposal instead of requesting a staff preview or confirmation.
    2. The flow continues at step 8 under that authority.
  * **8a.** Repeated or concurrent issuance request:
    1. The system returns the existing invoice or in-progress result without assigning a second number.
  * **9a.** PDF generation fails after issuance:
    1. The system retains the issued number and immutable snapshot with an incomplete PDF stage.
    2. The system retries the original document stage without issuing again.
  * **10a.** PDF preservation fails:
    1. The system retains the issued number and snapshot with an incomplete document stage.
    2. The system retries preservation of that original document without issuing again.
  * **11a.** Delivery fails:
    1. The system retains the issued invoice and separate [UC-20](UC-20.md) failure.
    2. The system resumes only [UC-20](UC-20.md) with the same number and PDF.
  * **12a.** Financial change requested for an issued invoice:
    1. The system routes correction to [UC-15](UC-15.md) without editing the original.
  * **12b.** View or download requested:
    1. The Operational User requests the preserved PDF.
    2. The system rechecks document access.
    3. The system provides the same original PDF.
