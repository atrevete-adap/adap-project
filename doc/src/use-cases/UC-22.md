## UC-22

* **ID / Code:** UC-22
* **Use Case Name:** Restore a validated backup
* **Description:** Restore an explicitly confirmed backup to an approved target and release operations only after recovery validation.
* **Primary Actor:** Super Administrator
* **Other Initiating Contexts:** None. A schedule never authorises or confirms restoration.
* **Supporting Actors:** None
* **Scope:** Turbine internal invoicing and collections application.
* **Level:** User Goal
* **Related requirements:** BR-01, BR-04, BR-06; UR: UR-14; FR: FR9, FR9.2; NFR-04, NFR-05, NFR-06.
* **Source:** E pp. 8-9, 12.
* **Stakeholders & Interests:**
  * *Super Administrator:* diagnose failures and recover a validated state.
  * *Turbine:* retain intact financial history and usable backups.
  * *Customer:* retain documents and scoped access after recovery.
* **Preconditions:** The actor is authenticated with Super Administrator recovery authority. A valid backup from [UC-21](UC-21.md) and an approved target exist. Restoration requires explicit human confirmation.
* **Postconditions:** The restoration retains duration and outcome. Normal operations resume only after data, document and permission validation passes; unsuccessful recovery remains incomplete.
* **Success Guarantee:** The confirmed target has validated invoice/PDF links, balances and permissions before idempotent jobs resume.
* **Minimal Guarantee:** Failed recovery is never declared complete. Normal billing remains blocked while validation fails; restored evidence cannot authorise duplicate financial work or weaken customer scope.
* **Trigger:** The Super Administrator requests restoration of a valid backup to an approved target.
* **Main Success Scenario:**
1. The Super Administrator selects a valid backup and approved target.
2. The system checks recovery authority and backup validity.
3. The system previews the restoration scope.
4. The Super Administrator explicitly confirms restoration.
5. The system restricts conflicting operations.
6. The system restores the selected data and documents.
7. The system validates invoice and preserved PDF links.
8. The system validates balances against financial evidence.
9. The system validates user permissions and customer scope.
10. The system records recovery duration and outcome.
11. The system releases normal operations after successful validation.
12. The system resumes eligible jobs from their recorded stages without duplicating prior financial work.

* **Extensions:**
  * **2a.** Recovery authority missing:
    1. The system rejects recovery without changing the target.
  * **2b.** Backup invalid:
    1. The system rejects recovery with the validity reason.
  * **4a.** Confirmation withheld:
    1. The system leaves the target unchanged.
  * **6a.** Restoration fails:
    1. The system records the failed recovery stage.
    2. The system keeps normal billing blocked.
    3. The system notifies the responsible operator.
  * **7a.** Invoice or PDF link validation fails:
    1. The system records incomplete recovery with the failed link stage.
    2. The system keeps normal billing blocked.
  * **8a.** Balance validation fails:
    1. The system records incomplete recovery with the failed balance stage.
    2. The system keeps normal billing blocked.
  * **9a.** Permission validation fails:
    1. The system records incomplete recovery with the failed permission stage.
    2. The system keeps normal billing blocked.
  * **10a.** Recovery exceeds the NFR-05 four-hour target:
    1. The system records the actual elapsed duration without claiming the target was achieved.
    2. The system exposes the failure in [UC-14](UC-14.md).
