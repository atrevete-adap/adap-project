## UC-15

* **ID / Code:** UC-15
* **Use Case Name:** Correct an issued invoice
* **Description:** Issue an approved corrective document linked to the preserved original invoice and explain the resulting balance.
* **Primary Actor:** Administrator
* **Supporting Actors:** None
* **Scope:** Turbine internal invoicing and collections application.
* **Level:** User Goal
* **Related requirements:** BR-04, BR-06; UR: UR-03; FR: FR2.3, FR2.8; NFR-04, NFR-05, NFR-06.
* **Source:** E pp. 3-4, 11, 14.
* **Stakeholders & Interests:**
  * *Administrator:* correct errors with authority and a reason.
  * *Customer:* receive an accurate adjustment.
  * *Accounting firm:* trace original and corrective documents without logging in.
* **Preconditions:** An issued original exists; the actor has correction authority and satisfies approval and closed-period rules.
* **Postconditions:** The issued correction is linked to the untouched original; balances reflect both documents and verified allocations.
* **Success Guarantee:** The authorised correction is issued with a preserved original link and auditable financial effect.
* **Minimal Guarantee:** Blocked/rejected corrections issue no document and never invent a refund/payment.
* **Trigger:** The Administrator selects an original invoice for correction.
* **Main Success Scenario:**
1. The Administrator selects the original invoice.
2. The Administrator enters the correction reason and proposed data or amount.
3. The system previews the original link and balance impact.
4. The system checks correction authority and closed-period rules.
5. The system performs [UC-05](UC-05.md) with the corrective proposal, appropriate series and original link.
6. The system performs [UC-19](UC-19.md) for the authorised corrective draft.
7. The system links the issued correction to the preserved original.
8. The system updates the financial view using both documents and verified allocations.

* **Extensions:**
  * **1a.** Unissued draft selected:
    1. The system routes editing to [UC-05](UC-05.md) instead of creating a corrective document.
  * **4a.** Approval threshold applies:
    1. The system invokes [UC-17](UC-17.md) for the exact corrective proposal before issuance.
  * **4b.** Approval rejected:
    1. The system retains the blocked proposal and rejection reason without issuing.
  * **4c.** Period locked without exceptional authority:
    1. The system blocks correction under [UC-18](UC-18.md) period rules.
  * **6a.** Issuance fails:
    1. The system retains the failed [UC-19](UC-19.md) stage for recovery without duplicating the corrective document.
  * **6b.** Delivery fails in [UC-20](UC-20.md):
    1. The system retains the issued correction and original link.
    2. The system resumes only [UC-20](UC-20.md) for the same number and preserved PDF.
  * **8a.** Cash refund needed:
    1. The Administrator routes the request to a separately authorised cash workflow.
    2. The system creates no refund or payment from the corrective document alone.
