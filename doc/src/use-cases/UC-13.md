## UC-13

* **ID / Code:** UC-13
* **Use Case Name:** Configure billing and automation policies
* **Description:** Validate and version global rates, numbering, billing, communication and approval settings for future operations.
* **Primary Actor:** Super Administrator
* **Other Initiating Contexts:** A separately authorised staff template editor may change communication templates within that capability only; this grants no global-configuration permission.
* **Supporting Actors:** None
* **Scope:** Turbine internal invoicing and collections application.
* **Level:** User Goal
* **Related requirements:** BR-01, BR-03, BR-04; UR: UR-13; FR: FR5.1, FR6.2, FR13, FR13.1, FR13.3; NFR-04, NFR-05, NFR-06, NFR-07.
* **Source:** E pp. 2-5, 9-10, 12.
* **Stakeholders & Interests:**
  * *Super Administrator:* control global policy changes.
  * *Operational staff:* use consistent templates and rates.
  * *Customer:* retain the terms on already-issued documents.
* **Preconditions:** Global changes require authentication as Super Administrator with the relevant configuration capability. A staff template editor must be authenticated with the separately granted template-editing capability and remains limited to that operation.
* **Postconditions:** A confirmed version records its effective scope/date, reason and actor. Issued invoice data and original documents remain unchanged.
* **Success Guarantee:** Validated configuration becomes available to eligible future operations without source-code changes.
* **Minimal Guarantee:** Invalid settings are not activated and historical invoices are never rewritten.
* **Trigger:** The Super Administrator requests a global configuration change, or a separately authorised staff editor requests a scoped template change.
* **Main Success Scenario:**
1. The Super Administrator selects a global billing or automation policy.
2. The system displays its current values.
3. The Super Administrator enters proposed values.
4. The system validates the proposed policy.
5. The system previews the effects on eligible future operations.
6. The Super Administrator confirms the change with its effective scope, date and reason.
7. The system stores the audited configuration version.

* **Extensions:**
  * **1a.** Insufficient configuration permission:
    1. The system rejects the protected operation.
  * **1b.** Separately authorised template editing:
    1. The staff template editor selects a communication template within their granted capability.
    2. The system restricts the operation to that template scope.
    3. The flow follows extension 3a and the same validation, preview and confirmation checks.
  * **3a.** Communication template change:
    1. The authorised template editor enters the Spanish or English template.
    2. The system previews missing variables.
    3. The authorised template editor requests a self-addressed test.
    4. The system requests test delivery.
    5. The system previews the reminder schedule.
    6. The flow continues at step 4.
  * **4a.** Invalid interval:
    1. The system rejects activation with the invalid interval reason.
  * **4b.** Invalid template variable:
    1. The system rejects activation with the missing or invalid variable reason.
  * **4c.** Invalid numbering rule:
    1. The system rejects activation with the numbering reason.
  * **4d.** Unsafe configuration combination:
    1. The system rejects activation with the conflicting policy reason.
  * **4e.** Proration convention unapproved:
    1. The Super Administrator documents the convention for approval before activation.
    2. The system leaves the policy inactive until that approval exists.
  * **4f.** Date-counting convention unapproved:
    1. The Super Administrator documents the convention for approval before activation.
    2. The system leaves the policy inactive until that approval exists.
  * **4g.** Rounding convention unapproved:
    1. The Super Administrator documents the convention for approval before activation.
    2. The system leaves the policy inactive until that approval exists.
  * **6a.** Scoped template editor confirmation:
    1. The authorised template editor confirms the validated template change with its effective scope, date and reason.
    2. The system stores the audited template version without changing unrelated global settings.
  * **7a.** Policy affects an already-issued invoice:
    1. The system preserves its original terms, amounts, identity and PDF.
